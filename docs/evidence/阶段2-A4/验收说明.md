## 打开与操作

打开 [开工检查演示](http://127.0.0.1:3000/projects/0dc8ca4c-77c2-40bf-9859-c66676a9ce2e/execution)。若服务已停止，在 Finder 打开产品工厂文件夹，双击“启动产品工厂.command”，看到“产品工厂已启动”后再打开。也可从首页进入“开工检查演示”需求页，点“技术方案与阶段计划 →”，再点“执行计划与开工检查 →”。

这是独立合成演示，不是用户业务验收或实际任务执行；数据保存在被 Git 忽略的 data/，不随代码提交分发。

1. 默认选择 T1，页首应显示“已保存 · T1 执行修订 6”。来源需求、技术方案和阶段计划均为修订 1，文件范围是 demo.txt。下方有完整步骤、产物、验证、零费估算、恢复和风险。
2. 点“查看服务器已保存计划”查看完整来源、文件指纹、原验收和十项闸门。正文可编辑；修改后出现“输入尚未保存”，必须点“保存执行计划”，不会自动授权或执行。失败保留输入，用“重新核对服务器记录”核对，再明确保存。
3. 看“本地零费操作范围”：当前演示授权已撤销，没有匹配授权。只有来源仍有效、明确文件、纯本地零费操作时，才能点击“核对本地范围授权”；预览全部已保存范围、填写确认说明、点“确认本地零费操作范围”，才会另存授权。授权仅记录范围，不执行项目。若当前来源过期，先按下方步骤核对来源。
4. 已有授权时，填写撤销说明、点“撤销本地范围授权”；重新检查后授权项应显示阻塞。只改验证措辞不扩大范围时，可保留原授权；实际操作、任务范围、文件指纹、费用、恢复或风险变化需要重新核对。其他任务的无关变更不要求重新确认这项任务的范围，来源有效性仍需检查。
5. 点“运行开工检查”。T1 最新历史检查为修订 4；原验收保留、文件已核对，授权尚未确认/已撤销，项目占用待验、执行器阻塞。“自动执行未开放”不可点击。当前检查留作快照，不能拿过去的已核对直接开工。
6. 在任务选择框选 T3，查看它已保存的执行草稿和开工检查；前置 T1、T2、S1 尚无执行证据，显示待验。计划确认不等于前置任务完成。T2 同属首个实现阶段、没有声明的前置依赖，检查应如实区分。
7. 在“查看执行准备历史”选择“T1 · 执行计划 · 修订 2”，应保留旧修改说明、原验证措辞及版本一文件指纹；当前修订 6 保留外部版本二的另存说明与新指纹。授权和撤销也能在历史中查看，历史确认不代表现在仍有效。
8. 刷新后草稿、检查与撤销保持。需要自行重启核对时，在启动终端按 Control+C，双击启动文件再打开同一地址，应仍有 T1 修订 6/检查修订 4、旧授权及撤销。不要删除或移动 data/。

A3 环境检查 15 分钟有效，过期后不能生成/保存新的执行计划或确认范围，但可保存检查阻塞与撤销旧授权。回“技术与阶段计划”，重新检查环境、选择新环境、保存并确认技术方案；逐项核对并保存/确认阶段计划后，回执行页重新读取当前来源，核对执行范围再保存。旧输入和历史保留，不能自动继承失效的开工结论。

外发、安装、发布、不可逆和付费操作可写为准备描述，本轮不能取得其执行授权；费用估计不是可靠报价，零估算不能成为外部调用零费结论。未来实际执行仍要重新检查、占用锁、有效预算和对应配方。未选文件、完整 Git 差异、外部进程及业务构建不在本轮事实检查范围内。
