# A20 接续摘要与审计｜核对步骤与阶段闸门

这是合成工程演示，真实模型与样例评分仍待验。保留当前工厂服务；关停后可双击根目录“启动产品工厂.command”。

## 一、打开与照着核对
1. 打开 [合成接续项目](http://127.0.0.1:3000/projects/24fd373a-114f-41a9-b628-3ac77a7e0087/handoff)。看到草稿修订2、冻结需求版本1并列、尚无有效通过范围、真实效果待验、任务与来源引用。环境过期会提示需核对；不会自动替换基线或开工。
2. 在“不可变摘要历史”下拉展开四版记录，选择早期版。看到原草稿修订1仍在，资料变化后显示需重新核对；下载按钮下载此版安全接续包。实际首版下载为2103字节，未包含原文档或代码，只保留安全摘要与引用；历史下载不替换成当前资料。
3. “项目审计与更正链”中展开第一版保存事件（时间12:59:42、对象58d88c55…），看到原理由与三次更正修订共存，更正不把待验改为通过。缺失/矛盾必须回原来源核查，不能按较新时间覆盖。
4. 要保存新摘要：填写理由→明确勾选→“确认保存接续摘要”。要追加说明：切换“追加审计更正”→选事件→填说明和理由→勾选→“确认追加审计更正”。这些只保存本机记录，不能执行任务、付费或外发。
5. 来源或更正链变化时，409显示在表单旁，文字与旧绑定保持；“刷新事实，保留输入”后先核对，再“核对并采用当前事实”，重新勾选才能提交。切换/离开确认选择取消，文字应保持；“放弃未提交输入”明确确认后才清空。Tab可从说明到理由。
6. 打开 [旧来源项目](http://127.0.0.1:3000/projects/ea1c5c20-652c-4d0b-94c7-5b663a01ea15/handoff)，展开旧事件，看到对象/版本/理由缺失明确标“未记录”，原记录未回填。
7. 打开 [恢复新身份](http://127.0.0.1:3000/projects/05d39fa9-39a3-45f2-831c-a2302333cdbb/handoff)，看到草稿0、无有效需求或授权/通过范围、恢复来源只读历史须重新确认。
8. 新合成项目已演示归档只读并取消归档，文件/记录均保留，没有任务重放。归档状态下只允许核对/下载已有摘要，不允许保存新摘要或更正。首版没有永久删除。
