## 打开与核对

直接打开 [技术与规划演示](http://127.0.0.1:3000/projects/793a9140-01d6-4ca2-b1a8-12838b39da47/planning)。服务在交付时保持运行；如果打不开，在 Finder 打开产品工厂文件夹，双击“启动产品工厂.command”，看到“产品工厂已启动”后再打开地址。也可在首页进入“技术与规划演示”需求页，点“技术方案与阶段计划 →”。演示数据在本机被忽略的 data/，不随 Git 提交分发。

1. 看页首“已保存 · 方案 4 / 计划 11”，检查记录时间、方法与局限；下方应有 Python 3.12.14、Node 22.23.2、Git 2.54.0、模型未启用和执行器待交付。缺工具不自动安装，目录权限标志不证明实际构建成功。
2. 看技术声明的需求理解、保留工程、方案、费用、暂缓项和风险。当前绑定演示冻结需求修订 1；规则建议可编辑，不保证业务方案正确。只有核对完整快照并填写说明、点击确认才会保存人工确认记录。
3. 向下看阶段计划，应有两个版本、五个阶段和五个任务，包括 S5 子阶段、T5 关联 R1；每项有范围、交付或需求/理由，依赖允许逐字输入逗号分隔编号。原需求验收与十项闸门都保留。
4. 点击“重新检查计划”，来源有效时看到“计划已确认，可交接”；此状态仅代表准备，没有执行权限或阶段通过结论。页面不持续轮询，实际交接前必须重新检查。
5. 在“查看规划历史”选阶段计划修订 7，再选当前修订 11，可核对旧快照与当前编辑不同。当前 T1 标题为冲突演示后明确保存的“本地输入仍保留，核对后明确保存”；旧修订 7 保留原标题。
6. 刷新页面后查看修订和确认；需要自行验证重启时，在启动终端按 Control+C，双击启动文件再打开同一地址，应仍有这些资产和确认。不要移动或删除 data/。

环境只在检查后 15 分钟内有效。超过时间后，“准备中/来源过期”属于正确行为，旧方案、计划与确认仍在历史中。重新核对时：点“检查本机与项目环境”，在“环境来源”选新记录，保存并核对确认方案；然后重新生成计划，或逐项核对旧计划并编辑、保存以绑定当前已确认方案，再核对并确认计划。不能自动继承旧确认。没有需求基线的项目可检查环境，不能生成可确认方案。

已验证循环和冲突；如需自己修改，请使用演示。输入 S1 依赖 S2，而 S2 已依赖 S1 时，草稿可保存但出现循环阻塞、不能确认；恢复正确依赖后重新检查。确认草稿不触发付费、外发、安装、项目脚本、文件写入或部署。
