# 阶段 2 A5 技术开发文档｜补丁预览与安全写入

> V1.1，2026-10-08；V1.0 已在编码前形成，V1.1 补充实际验证与边界。先文档，再开发验证，最后本地提交。依据主 PRD V1.1 FR09、FR08 和 AGENTS；沿用阶段 1 技术适配。A1—A4 待验保留，不宣布阶段通过。

## 一、阶段目标
交付人工提供候选文本 → 不可变补丁预览（文件、完整差异、需求关联、验证计划）→ 核对并明确确认 → 授权范围内实际文件写入 → 可持久查询结果的链路。
只实现固定的本地文本写入配方，不引入模型生成、任意命令、安装、发布或通用自动任务执行。任务成功仅说明文件配方执行结果，不能替代工程验证和阶段验收。
FR09 数据库变更要求保留：本配方阻止数据库、迁移及依赖配置；将来另列迁移和数据备份方案。代码恢复不等于数据恢复。

## 二、技术适配摘要
延续 FastAPI/SQLite/Alembic 与 Next.js 纵向切片，不换技术栈、不增加依赖。
补丁写入需要独占锁、短事务授权检查、耐久记录与失败补偿，属于 FR09 的安全前提；不提前交付 FR10 命令执行器或 FR11 通用长任务平台。

## 三、技术栈与模型
Python 3.12 标准库提供目录描述符、禁止跟随链接、文件锁、原子替换和落盘；SQLAlchemy/Alembic 追加资产与运行表。
本轮不调用模型，不改原阶段预算，不新增费用或数据外发。真实模型仍待验。

## 四、环境与配置
沿用后端 127.0.0.1:8765、前端 127.0.0.1:3000、已授权根目录与后端本机令牌。
数据和恢复副本存于忽略的 data/，目录 0700、副本 0600；不给用户密钥填写新要求。
平台自身工程、运行数据库与秘密目录不作为业务补丁目标。实际演示只写新建的合成演示项目，保留用户已有项目。

## 五、项目结构
追加 patches.py（流程、持久运行、恢复）、patch_files.py（受控文本读取/写入）、patch_schemas.py（契约）、0005 迁移、补丁验收页与相关测试；保持现有结构。

## 六、数据、资产与状态
PatchAsset：id、project_id、execution_id、payload、created_at。payload 保存原文/候选/完整差异、前置指纹与目录身份、来源、需求验收和验证计划；不可变，本机长期保存，不记入日志。
PatchRun：id、project_id、patch_id、state、details、created_at。幂等请求绑定同一运行；保存前置备份、开始写入状态，再执行文件替换。状态为 preparing → applying → applied；错误进入 failed / rolled_back / rollback_required。
执行占用由项目根目录独占文件锁约束。多个登记目录重叠且可能触碰另一项目时阻止写入。
失败恢复只处理仍匹配原文或本次候选的文件；外部第三方内容保留并停止自动恢复，原文及候选保留。启动时恢复未结束写入，不能盲目重放。补偿式多文件恢复不宣称跨进程原子事务。

## 七、API / 工具设计
前缀 /api/v1/factory/projects/{id}/patches，POST 均要求本机来源和幂等键，统一 error.code/message，无堆栈。
- GET：项目补丁与运行历史；GET /assets/{id}：完整补丁及当前可应用原因。
- POST /preview：execution_id、expected_hash、files[{path,content}]、validation_plan；返回补丁 id/hash、完整差异与关联。不写工程。
- POST /apply：patch_id、expected_hash、confirmed=true、reason；重新检查后返回持久运行及结果。运行状态可 GET 查询；限量同步执行，不无限等待。
- POST /recover：run_id、confirmed=true；只恢复能确定属于本次写入的内容，外部内容冲突不覆盖。
上限默认：1—5 文件，每份原文/候选 UTF-8 文本不超过 64 KiB，原文与候选合计 256 KiB；目录必须已存在，只新增或替换文本，不删除、改名、建目录。
路径须在 A4 显式文件清单中：拒绝绝对/遍历/链接/硬链接/设备/二进制，以及 .env、秘密命名、依赖目录、原始数据、数据库、迁移和依赖配置等。候选或原文发现秘密不存储、不回显；检测并不能代替操作者核对。
应用条件：当前已确认来源/环境、当前执行版本、零费本地 code_write 范围授权未撤销、全部选中文件前置一致、无未交付的依赖结果、可取得独占锁、无待恢复运行，且已看具体补丁并明确确认。授权在每个写步骤重新检查。
冲突、失效、占用、保护路径拒绝；失败/冲突运行可查询，不把恢复失败当成功。重复确认同一补丁不会再写一遍。

## 九、验收界面

展示当前阻塞原因和持久历史；应用成功后明确“仍需工程验证”，原输入保留。编辑后不能使用旧预览确认；未保存输入离开提醒，网络失败重试保持同一幂等键。
