# 阶段 2 A4 技术开发文档｜执行计划与开工检查

日期：2026-10-08。版本：V1.1 工程交付与待验（先形成 V1.0，开发验证后补入实际结果）。依据：PRD V1.1 FR08，必要 FR05/FR07/FR14/FR21/FR24；通用手册第二、三部分；阶段 1 与 A3 适配声明。产品负责人在 A3 回执明确下一步 FR08 后回复“开始吧”，授权本轮范围内工程推进；原待验保留，不视为真实调用、资料外发、收费或业务项目写入授权。顺序：本文档 → 实现验证 → 证据及状态 → 本地提交。

## 一、阶段目标

已确认的阶段计划中选一项任务，形成可审查的执行计划，展示来源版本、预期修改、步骤、产物、验证、费用估计、恢复及风险，再持久化开工检查。没有执行器必须明确阻止自动开工，不能把准备记录当成任务成功。

本轮覆盖 FR08 的计划与确定性检查，不提前实施 FR09 补丁写入、FR10 命令执行、FR11 长运行恢复或发布。任务依赖尚无执行证据时显示待核对，不能人工勾选成自动成功。没有有效阶段计划不能生成新的执行草稿，但旧草稿、检查与授权仍可查看或撤销。

## 二、技术适配摘要

沿用 FastAPI/Pydantic、SQLite/SQLAlchemy/Alembic 与 Next.js/TypeScript，增量实体与项目内最小核对页；不替换依赖、修改原项目或引入云资源。任务与业务基线来自 A3，原验收文本和十项闸门由后端带入，不能由执行草稿删减。草稿明确为规则建议或用户编辑，业务合适性仍须人工核对。

## 三、技术栈与模型

无新增模型契约或 Prompt，不调用模型。操作类型为本地只读、代码写入、模型外发、依赖安装、发布、不可逆动作；本轮这些均只是准备描述，自动执行能力未交付。涉及外发/付费/发布/不可逆的准备计划可以展示风险，但本轮不提供有效执行授权；未来要有具体可审查结果和对应能力才能开放。本地零费用代码修改范围可单独确认或撤销，依然不能实际执行。

## 四、环境与配置

沿用本机 3000/8765 和服务端访问保护、授权根目录，不新增配置或要求 Key。环境事实复用 A3 有效来源，15 分钟过期后需重新检查与确认来源。

外部变更只核对显式选择的相对文件：最多 20 个，每文件最多 256 KiB，总计最多 2 MiB，保存哈希/大小/存在性，不保存内容。拒绝绝对路径、上级穿越、秘密与数据/依赖/版本库目录、符号链接链、非普通文件和无法核对的文件。不存在的目标文件记录为拟新增，不创建文件。选中文件内容命中秘密时停止核对，错误不回显内容。未选文件、完整 Git 差异和外部进程未覆盖，必须明确局限，不能称作全仓库检查。

## 五、结构

- execution_schemas.py：严格执行计划、来源、文件指纹、授权、检查和工作区结构。
- execution.py：追加资产、来源核对、限定文件事实、权限影响哈希及检查矩阵。
- db.py / Alembic 0004：新增 execution_assets，旧数据不重写；迁移前本机备份。
- 项目 execution 页面：选择任务、编辑和保存执行计划、完整授权预览、撤销、检查与历史。
- test_execution.py：真实业务规则测试，保留 A1—A3 104 项。
- docs/evidence/阶段2-A4/：截图、可打开地址、操作步骤、是否表。

## 六、数据与状态

ExecutionAsset：id、project_id、task_id、kind、revision、planning_id、payload、created_at；kind=plan/check/grant/revoke，按项目/任务/种类递增、追加不可变。计划关联 A3 不可变资产，服务端持久化基线、方案、环境、阶段任务、原验收与闸门。检查记录绑定执行修订与内容哈希，保存当时结果、检查方法、时间和局限，历史检查不冒充当前有效结论。

计划正文：修改说明、选中文件、步骤（类型、描述、产物与验证）、费用估计微元、恢复、风险。步骤最多 20；字段有长度和非空约束；不允许任意 Shell 执行。新执行修订不覆盖旧授权或检查。

授权只覆盖显式预览中的本地零费代码修改范围，不覆盖外发/安装/发布/不可逆。权限影响哈希由任务标题/相关需求/范围、操作描述、选中文件、文件指纹、费用、恢复和风险计算；只改验证措辞时旧范围授权可继承。改变实际操作或文件/费用/风险需重新确认。无关任务不跨用授权；撤销永久记录并即时阻止该授权，撤销后可以重新核对产生新授权。

只读检查在已登记本机范围内可直接推进，无新外发或费用。授权确认不要求执行器已交付（仅确认未来本地修改范围）；所有检查仍报告执行器缺失。can_start 始终 false，手动执行待核对，不能显示运行或成功。无占用登记系统/任务依赖结果时标待验，不虚构“空闲”或“依赖完成”。本轮不建立会被误当成真实运行的占用锁。

## 七、API

统一前缀 /api/v1/factory/projects/{id}/execution。POST 继承 Origin、服务端令牌、Idempotency-Key 与数据库单写事务；错误统一 error.code/message。同步有界检查，无 SSE/无限请求。

| 接口 | 请求 | 响应 | 主要错误 |
| --- | --- | --- | --- |
| GET / | 无 | 当前有效候选任务、每任务最新执行草稿/检查/有效授权与历史摘要，自动执行未交付 | NOT_FOUND |
| GET /assets/{id} | 无 | 所属项目不可变资产 | NOT_FOUND |
| POST /plans/generate | planning_id、task_id、expected_revision | 规则执行草稿 | PLAN_BLOCKED、NOT_FOUND、REVISION_CONFLICT |
| POST /plans/revisions | 同来源与修订、正文 | 用户编辑执行修订、来源和范围哈希 | INPUT_INVALID、PATH_FORBIDDEN、FILE_UNAVAILABLE、INPUT_STALE、REVISION_CONFLICT |
| POST /check | execution_id、expected_hash | 新的持久化检查矩阵、can_start=false | REVISION_CONFLICT、NOT_FOUND |
| POST /authorize | execution_id、expected_hash、说明 | 明确本地范围授权记录 | AUTHORIZATION_UNSUPPORTED、INPUT_STALE、REVISION_CONFLICT |
| POST /revoke | authorization_id、说明 | 不可变撤销记录，重复不重复生成 | NOT_FOUND、REVISION_CONFLICT |

来源不满足时可运行“检查”并留下具体阻塞，不允许借新草稿或授权掩盖失效。检查覆盖：当前需求/方案/计划确认与环境、任务/阶段/版本依赖、原验收、授权、预算余额与可靠报价、显式文件变更、项目占用与执行能力。本地零费读取不消费或预留模型预算；涉及付费估算时只能展示实际预算事实，报价与能力未接入不能运行。执行授权不取代 A2 资料外发授权。

## 八、Prompt 与安全

无 Prompt，无外发上下文；全部描述是准备资料，不解析为工具调用。禁止用户文本自授权限或改写规则。任何客户端传入“已通过/可运行/已执行”均作为额外字段拒绝；检查及授权有效性由后端计算，前端隐藏按钮不能替代校验。审计仅保存对象/修订/哈希/作用，不记录全文或秘密。

## 九、最小验收页

A3 页面新增“执行计划与开工检查”入口。选任务后生成规则草稿、逐字段编辑并显式保存；本轮采用显式保存，避免费用/修改范围的半输入自动变成授权预览。失败和冲突保留当前输入，服务器记录单独核对，明确保存后才覆盖；离开未保存提示。保存、检查、授权前展示完整范围快照；本地授权需人工说明并确认，撤销立即持久化。历史可查看，页面醒目标注不执行。四宽度、键盘实际验收，原生缩放/真机仍待验。

## 十、验证

保留原测试；新增来源缺失/失效、跨项目和任务、修订并发/幂等、严格结构/空白、文件穿越/秘密目录/符号链接/FIFO/超大/新增/外部变更、确认哈希、授权影响继承与撤销、付费外发不伪授权、预算不重置、必要检查保留、执行器和依赖缺失不能开工、旧资产不可变及重启恢复。

实际合成演示：生成已确认来源 → 选任务 → 编辑计划与文件范围 → 授权完整预览 → 检查显示执行器等阻塞 → 无关验证编辑继承授权 → 撤销生效 → 保存冲突保留输入 → 外部选中文件变动阻塞 → 最终重启核对。演示文件变动由开发执行者在独立合成目录模拟，不操作用户项目。

## 十一、产品负责人核对

1. 在演示规划页点击执行计划入口，看到任务与来源修订。
2. 生成草稿，核对修改、步骤、产物、验证、费用、恢复和风险；选择相对文件后显式保存。
3. 查看完整本地零费范围预览，填写说明确认，看到可撤销的范围授权，而不是任务已运行。
4. 点检查，看到原验收保留、已核对/阻塞/待验分类和解除方法；自动执行始终不可操作。
5. 只改验证措辞并保存，原本地范围授权保持；改实际步骤或文件后需重新授权。
6. 撤销后授权失效；刷新/重启仍保留草稿、检查、授权及撤销历史。

## 十二、限制与待确认

无新增必须业务决策；既定权限、预算、留存不重复询问。本轮纯工程推进依据最新“开始吧”，保留 A1—A3 待验和依赖风险，不宣布阶段通过。不完整 FR08 自动开工能力以明确阻塞方式交接，而非伪造通过。100 项目/1000 任务性能、完整 Git/外部进程检测、实际写锁及执行配方属于后续能力，不能以此小演示宣称全量验收。费用估计不是实际报价或已发生费用。

## 十三、后续交接

FR09 补丁预览/安全写入、FR10 受控配方等后续复用来源、范围授权和检查矩阵；须新增实际写锁、进程状态和执行前即时核对，不能直接消费历史“通过”记录开工。本轮没有执行入口或执行任务，后续仍先文档、再开发验证、最后提交。
