# 阶段 2 A19：备份导出与归档

版本：V1.1；2026-10-09。V1.0 已在代码变更之前形成；本节之后补充实际交付结果。

## 1. 依据与边界
主 PRD V1.1 FR23：导出业务数据、文档、证据和产物清单；选择代码打包或版本引用；秘密默认排除；恢复前检查完整性、版本、目录和冲突；恢复新身份保留来源、不重放运行或收费；归档不删除，活动/未知运行不能归档，取消归档只恢复可见性。
沿用 D6 长期本机留存与不自动外部备份。用户“继续完成下一步”授权本切片工程，顺序为文档、开发验证、证据与状态、最后本地提交。不创建付费资源，不调用模型或对外发送。

## 2. 推荐实现
单项目便携 JSON 备份（.pfbackup.json），结构版本 1、工厂数据库版本 0008；业务表历史、文档、证据报告及产物/文件清单独立保留 SHA256。完整包上限 8 MiB，单文件 512 KiB、清单最多 500 项；超限拒绝或明确列为未包含，不能冒充完整磁盘备份。默认附安全文档，代码可选择内容或只引用文件摘要及 Git 版本。图片/二进制/大文件仅列清单，理由说明，原文件不删除。秘密路径、凭据、个人信息与不可安全核验内容排除，排除项可查看；本机密钥和配置从不打包，恢复后需重新配置。

## 3. 恢复语义
只恢复到允许根目录内的全新目录，展示新增文件及原业务历史数量、替换范围为零；已有目录/登记/链接/嵌套业务目录冲突拒绝。工厂自身若作为只读项目登记，其扫描排除的 data/ 作为托管容器，可新增独立恢复项目；不会改动工厂业务代码或已有数据。备份视为不可信资料，严格校验结构、版本、每项摘要、大小、路径及敏感信息。预检持久化、确认时再次核对，幂等写入，新 UUID 保留原项目身份与备份摘要。历史保存为只读来源快照，不把旧授权、运行、验收或费用记录导入活动流程，不改全局预算；当前项目需要重新确认需求、授权与验收。旧费用仍可追溯但不再次计费。文件独占创建，异常仅清理本次未修改的新文件；原项目从不覆写。恢复中断后遗留目录视为冲突，不自动续写。

## 4. 归档语义
归档/取消归档追加历史与理由，携带当前版本摘要和显式负责人确认。写事务内校验命令、补丁、模型活动及未知结果；未知或暂停需先核对，不凭归档解除占用。归档项目默认从首页隐藏，可查看归档列表、历史和备份；后端在同一单写事务阻止其他业务写操作，取消归档不重放任何任务。永久删除不实现。

## 5. 接口契约
沿用本机认证、Origin、幂等键及统一 error.code/message，无堆栈。
GET projects/:id/backups：状态摘要、归档标志、历史、恢复来源与清单。
POST backups/exports：expected_state_hash、include_code、confirmed、reason；返回不可变备份记录。
GET backups/exports/:asset/download：受控 JSON 文件下载，最大 8 MiB。
POST backups/previews：备份文件名、JSON 字符串、target_path、confirmed、reason；返回检查结果和新增/替换范围。上传请求最大 12 MiB、合法扩展和 UTF-8 JSON 真实类型；不执行或解压附件。
POST backups/restores：asset_id、expected_hash、confirmed、reason；返回新项目身份和来源记录。
POST backups/archives：expected_state_hash、archived、confirmed、reason；返回归档记录。冲突 409、结构 422、秘密或不兼容/完整性错误拒绝，原输入与历史保留。

## 6. 持久化与兼容
复用 RequirementRecord 保存备份、预检、恢复来源与归档事件，不新增数据库迁移或依赖。历史业务表逐项导出，幂等请求与访问配置不导出。旧项目默认未归档；ProjectOutput 新增可选 archived 布尔字段，旧字段不变。归档列表通过显式查询读取。

## 7. 最小验收界面
