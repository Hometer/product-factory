# 阶段 2 A9 技术开发文档｜AI 提供方与能力配置

> V1.1，2026-10-09。V1.0 在编码前形成；本版补录实现与验证。依据主 PRD V1.1 FR13、AGENTS、通用手册第二/三部分；先文档、再开发验证、最后本地提交。A8 已提交 a991549，原待验保留。

## 一、阶段目标

复用 A2 单一北京百炼接入，补齐六项能力说明、配置状态/固定掩码、离线契约与真实验证区分、每次调用的脱敏回执和版本关联。文字/结构输出/用量计费已有受控实现；流式输出、代码生成、提供方请求查询在本平台尚未接入，必须显示不能运行。最多一次结构修正，共两次，仍受原授权/预算约束。自动切换保持关闭，无开启接口。首版至少一个接入的真实契约仍须 Key 验收，不能用离线结果冒充。

## 二、技术适配摘要

沿用 FastAPI/SQLite/Next.js/httpx，无新依赖，不重新实现 A2 外发预览、密钥保存、候选采用或预算。新增只读提供方页/回执，非正式前端铺开。无新增费用、外发、付费调用或云资源。

## 三、技术栈与模型

沿用已定 qwen-plus-2025-12-01 非思考模式与已批准北京地址。官方 OpenAI 兼容文档确认文字/用量字段与北京地址，服务商支持不等于本平台已接入/已真实验证。不更换模型、不刷新费用报价或宣称新报价已验；A2 2026-10-08 报价及 30 天有效期沿用，真实启用前仍核对。官方依据 https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope 、https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions （2026-10-09 查阅）。

## 四、环境与配置

本机 3000/8765；密钥仍保存在忽略 .env（0600），响应仅配置状态和固定掩码，不展示任何真实前后缀。保存配置不连网、不验证真实能力。适配器/模型不匹配、无 Key、配置损坏或报价过期显示阻塞，手动需求仍可用。无新增必须业务问题；真实 Key 通过原密码框配置，聊天不索要或回显。

## 五、项目结构

新增 provider_capabilities.py/provider_schemas.py、契约测试、settings/provider 验收页；models.py 在现有调用处记录耗时、受限请求标识与验证结论，保留原 API/错误处理。主页/需求页增加入口，代理只允许新只读端点。

## 六、数据、资产与状态

复用 RequirementRecord 的追加型 provider_receipt 资产，不为目录完整新增数据库或重写旧 payload。字段为运行/项目、尝试号、来源 mock/real_cloud、模型/地址、适配器摘要与契约版本、记录时间、请求标识（可空）、耗时、是否已发送、文字/结构/用量验证、tokens/费用（未知为 null）、错误码。无密钥、完整文档、原始响应或日志原文。与调用尝试/费用结算在同一事务落盘；旧记录缺字段显示“未记录”，不回填成通过。

当前六项能力分别展示平台实现、离线契约状态、匹配当前模型/地址/适配器版本的真实成功回执数、能否在有效批准后调用。已配置不等于已真实验证；真实验收未完成仍明确待验。未接入能力一律不可运行，真实请求编号不等于具备提供方查询接口。Mock 回执永远不提高真实计数。

能力观察是单次事实，不承诺所有输入效果；改适配器/模型/地址后旧观察仅为历史，不计入当前真实验证。未知用量或外部结果保留全部预算、不自动重发。一次修正前重检来源/授权；每次修正占用原授权次数、尝试次数与预留预算，仍不合规明确失败、不写正式决策。

## 七、API / 工具设计

GET /api/v1/factory/model/provider：类型化配置摘要、固定掩码、当前版本、六能力/阻塞、预算、最近 100 条脱敏回执（保留总数），无连网或新资产写入。继续保留 /model/status、/model/config 等原接口。配置错误统一 error.code/message，不泄露配置原文。无新增付费执行或能力开启 POST；既有配置保存仍独立于调用。

原 Run.attempts 增量可选 request_id/elapsed_ms，历史缺失正常兼容。上游请求标识只接受 chatcmpl- 受限编号、32 位十六进制或 UUID，且拒绝当前密钥/本机令牌、秘密特征和个人信息；不允许作为 URL/命令。无长耗时新接口或 SSE；模型分析沿用提交任务/轮询，未支持流式明确禁用。

## 八、Prompt 设计

沿用 requirements-v1，模型只能生成候选。结构校验、秘密筛查、显式引用检查和人工采用仍在确定性代码。修正一次不添加新资料，不写正式决策、不修改授权和验收结论。

## 九、验收界面

进入“AI 提供方与能力”：顶部显示未配置/已配置、固定掩码、真实验证待验；六能力列显示离线与真实状态。右侧显示预算/授权限制、自动切换关闭；下方按项目查看脱敏调用回执。配置入口链接原需求页，配置本身不调用模型。不显示秘密；无 Key 空历史如实展示。四宽度和键盘检查。

## 十、测试要求

保留 318 项。新增六能力/无 Key/过期/型号变动/无权限、密钥掩码/配置不外发、HTTP 适配器请求与响应契约、初始化/超时/非 200/超长/畸形响应、请求编号秘密过滤、单次耗时、Mock 不变真实验证、匹配版本/地址隔离、回执持久化重启、一次修正与费用/次数/撤销、未知费用保留/无重发。Ruff/mypy、前端 Lint/类型/构建、实际浏览器四宽度与真实服务重启，旧业务行逐行保持。

真实模型冒烟无 Key 写待验；未来须具体项目资料/额度批准后跑非敏感样例，记录编号/耗时/tokens/费用、结构首测与修正区别，再由负责人对 5—10 样例评分。不能因保存 Key 或离线契约通过而标真实能力通过。

## 十一、产品负责人验收清单

- [ ] 未配置时无运行承诺；流式/代码生成/请求查询明确不可运行。

- [ ] 看每次回执来源、次数、用量/费用；未知不能显示零费成功。

## 十二、风险与待确认项

无新增必须业务决定，用户已授权 FR13 范围内工程。首版至少一个真实契约、真实效果/评分仍待验，原生缩放/真机及旧依赖风险保留；A9/阶段 2 不宣布通过。仅一次观察不能确认整个能力或所有规模性能；官方资料不是实际网络验证。模型无法自行扩大能力或启用切换。

## 十四、实现与验证回执

2026-10-09 最终后端 348/348（原 318 保留，新增 30），Ruff/mypy 和前端 Lint/类型/生产构建通过。隔离 HTTP MockTransport 验证 JSON 模式、非思考、非流式、无工具字段、受限响应和请求编号；不是实际云模型调用。结构无效只修正一次，两次费用与授权计数分别保留；修正前撤销授权不发第二次。仍失败不创建正式决策；错误模型、未知用量、已发失败保留预算，不自动重发。适配器摘要在进程启动时固定，覆盖调用实现、候选结构与 prompt；改文件须重启，旧进程不能冒充新版本。

新增测试最初误读 FakeProvider 属性、误将夹具内既有人类决策当成模型新增决策，均改为实际捕获修正参数与逐行比较调用前后决策，没有删测试或放宽要求。前端最初在 effect 同步设置状态触发 Lint，已改为异步读取结果；没有屏蔽规则。

实际 ego-browser 空间 1 检查 390/768/1280/1440、六能力、未配置阻塞、真实待验、零回执、刷新、主页/需求页入口与键盘。品牌到返回再到刷新可用 Tab；主页增加入口后采用局部换行布局。需求页有效临时输入触发原有 800ms 自动保存：合成演示追加修订 10，随后追加修订 11/12 恢复原内容；历史基线 5、所有原业务行保持。改用不足三个字的无效输入复验离开确认，拒绝离开后输入保留，未保存；失败截图已替换为真实复验截图。没有改写或删除测试历史。
