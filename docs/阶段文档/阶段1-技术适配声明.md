# 技术适配声明

日期：2026-10-08。版本：V1.0，产品负责人已回复“确认，继续”，三项核对通过。适用对象：产品工厂平台自身；不统一替换被接入项目的技术栈。

推荐建设本机 Web 工作台，以 SQLite 保存权威业务状态，以受控本地执行器操作经授权目录，以一家国内模型服务提供候选内容。采用最小纵向切片：先完成项目、需求和人工确认闭环，再扩展执行与交付。首版 FR01—FR24 的 P0 范围全部保留；本声明形成时尚未实现业务功能，后续进展见项目状态。

## 1. 产品形态判断

- 产品类型与核心任务：本地优先、单人多项目的 AI 辅助研发与交付平台，组织需求、有效决策、执行、证据与接续。
- 核心交互：分阶段确认与受约束工具调用；人工回答、补丁预览、效果评分是业务流程的一部分。
- 开发路径：纵向切片。采用正式 Web 技术做最小核心交互，不提前实现全部导航和视觉系统；正式前端扩展放在阶段 3。
- 当前阶段范围：技术适配、需求覆盖和子阶段顺序、数据与执行边界、验证计划及费用说明。本阶段不安装业务依赖、生成业务代码或调用模型。
- 交付目标：macOS 本机使用，仅回环访问。公网、局域网匿名执行、多人协作、云端执行器、自动部署不属于首版。

## 2. 采用的默认方案

| 方案 | 采用原因与边界 |

### 模型接入推荐

推荐阿里云百炼华北 2（北京）的 `qwen-plus-2025-12-01` 快照，非思考模式，通过官方文档支持的兼容接口接入。固定快照以便追溯，停服或能力变化时明确报告，不自动换模型。官方资料列出该快照的北京地域和结构化输出能力；实际接口契约与业务效果尚待真实验证。[模型与快照说明](https://help.aliyun.com/zh/model-studio/qwen-plus)、[结构化输出说明](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。

模型只返回 PRD、计划、补丁或摘要候选；后端校验后保留为草稿。模型不得直接批准外发、修改预算、执行任意命令或更新验收事实。JSON 字符串合法不等于业务结构正确，仍需 Pydantic 校验。

推荐每次尝试最多 16,000 输入 token、4,000 输出 token，关闭联网搜索等额外功能。官方模型页的北京、输入不超过 128k 档位非思考原价为输入 0.8 元、输出 2 元/百万 token；按上述上限测算每次尝试约 0.0208 元，三次尝试约 0.0624 元。此测算不是保证费用或效果，调用前需核对实际账号、快照、报价、输入上界及有效授权；不能依赖免费额度放行。[官方价格及计费档位](https://help.aliyun.com/zh/model-studio/qwen-plus)。

已定上限为每次任务 2 元、每个开发阶段合计 100 元及 100 次请求，重试计入。平台自身验证与被生产产品验证分别记账；开发阶段的总费用不得因拆子阶段重置。此处预留规则是实现要求，不表示预算系统已实现。

北京服务的官方接口示例使用北京地域 API Host，接入时从账号配置核对 Host，不硬编码其他地域。国内端点不等于零留存：官方数据留存政策描述服务端缓存及可选规则，具体模型与账号是否适用必须在接入时核对。不上传敏感资料，不承诺未经核实的零留存或全部内容不被训练。[兼容接口](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)、[官方数据留存政策](https://www.alibabacloud.com/help/zh/model-studio/data-retention-policy)。

当前外部平台只有预期的模型服务，不注册云计算资源、购买专享推理资源或创建收费存储。本声明尚未执行模型请求。

### 数据与安全边界

SQLite 为业务事实权威来源；项目文档是可交接投影。同步记录摘要和修订，外部手改生成待核对差异，不双向静默覆盖。项目、基线、决策、授权、阶段、任务、运行、产物、检查、评测、预算、费用、发布和审计按阶段引入；不会先创建所有空模块。

需求与验收快照不可变，更正追加修订。金额采用定点整数和币种，时间内部 UTC、显示 Asia/Shanghai。请求修订冲突返回明确错误；具有副作用的请求使用幂等键，重复键但请求内容不同返回冲突。

首版只有本机操作者，仍需后端校验项目归属、批准责任与访问来源。推荐浏览器经本机前端服务代理 API，后端令牌仅供服务端使用；不把模型 Key 或后端执行令牌打包进浏览器。代理和后端都校验 Host、Origin 及允许路径，不以回环监听代替鉴权。

文件路径解析真实目标，越界符号链接与秘密文件拒绝访问；新建不能覆盖已有内容。上传验证格式、真实类型、大小和安全文件名；文档里的指令只作为资料。风险扫描不足以证明任意资料没有秘密，外发仍需用户选择资料及项目策略。

已定留存：业务记录、授权、验收、审计与证据长期本机保存；脱敏执行日志 30 天，仍被有效证据引用的唯一材料不清除；原文件不自动删除。该规则覆盖技术设计中普通审计 180 天的建议，依据是本轮已确认的长期留存决定。

### 首版分阶段覆盖

下表是建设顺序，不是削减首版范围。每个子阶段须先出独立技术开发文档、记录验收及证据，然后才开发与提交。

| 批次 | 核心范围 | 主要通过条件 |
| --- | --- | --- |
| A 项目与基线 | FR01—FR07；必要 FR14、FR24 | 新建、只读接入、草稿确认、不可变基线与计划闭环；原项目不被修改；决定重启可恢复 |
| B 受控执行 | FR08—FR14；最低 FR05、FR21、FR24 | 真实任务可执行，写锁、路径、授权与预算生效；重启核对，暂停取消阻止新步骤，未知副作用不盲重试 |
| C 验证与交付 | FR15—FR20 | 工程与真实模型分开记录，评分与有效证据绑定版本，待验阻止通过；可核对交付包 |
| D 治理与接续 | FR21—FR24 完整化 | 模板升级保留定制、费用不重置、导出恢复与归档正确、接续独立可用 |
| 正式前端与整体验收 | 上述完整 P0 页面与 FR/AC 全覆盖 | 390/768/1280/1440 宽度、200% 缩放、键盘流程，以及 AC01—AC24 和真实效果均核对 |

批次 A 计划先拆“项目登记与只读接入”，再做“需求确认与基线计划”。具体接口、实体和本轮完成边界在阶段 2 首个子阶段文档定义。阶段 1 没有批准一次实现全部批次。

三类试点在需要实际接入时由用户选择目录，先只读预览；不会默认关联或修改其他项目。当前无需提前追问所有试点与写入授权。

## 5. 强制底线检查

| 项目 | 当前结论 | 实现与验证计划 |
| --- | --- | --- |
| 密钥与隐私 | 规则已定，实现待验 | `.env` 忽略、前端与日志排除、外发最少上下文、交付白名单及扫描 |
| 数据与任务可恢复 | 方案明确，实现待验 | 数据库事务、修订与运行检查点；强制结束进程后实际核对；预算不重置 |
| 输入输出校验 | 方案明确，实现待验 | Pydantic 严格结构、上传真实类型校验、模型只生成候选 |
| 错误与日志边界 | 方案明确，实现待验 | 统一 `{"error":{"code":"…","message":"…"}}`，可补 retryable/details/request_id；不返回堆栈或完整资料 |
| 模型异常处理 | 方案明确，实现待验 | 初始化、网络、超时、限流、结构错误兜底；安全步骤总尝试最多三次，结构修正最多一次并占额度；付费未知先对账 |
| 人工确认与权限 | 规则已定，实现待验 | 后端约束预算、状态迁移和验收；操作计划不得扩大授权 |
| 测试与真实模型 | 尚未运行 | 自动测试覆盖恢复、并发幂等、预算最后额度和安全失败；真实模型 5—10 条代表样例由用户评分 |

性能验收在本机设备上以 100 项目、每项目 1000 任务准备数据，执行 100 次非模型列表查询核对 P95≤2 秒；排队拒绝≤2 秒、步骤更新一般≤3 秒、重启核对≤60 秒分别实验。布局使用四宽度及缩放/键盘；真机结论只在实际设备验证后填写，不用浏览器尺寸模拟代替真机事实。

阶段闸门出现否或真实模型待验时如实保持待验；允许提交已验证工程进展，但提交不代表阶段通过。缺 Key 时不靠 Mock 宣布完成。正式上线必需项不使用分期例外跳过。
