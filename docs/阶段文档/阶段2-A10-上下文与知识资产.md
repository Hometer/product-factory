## 六、数据、资产与状态

复用 RequirementRecord 的追加型 context_bundle，无新表或迁移。持久 schema_version、阶段、任务、需求/基线/方案/计划版本、所选来源、每项来源版本/摘要/定位/来源性质、安全片段、字符上限/实用量、遗漏原因/字符数、固定权限说明。索引读取不写资产；保存需当前索引哈希与幂等键，冲突保留输入。历史快照不可覆盖，重启保留。

索引包含当前需求字段/条目、最新冻结基线、必要决策和最近五次需求历史；规划与执行阶段增加当前方案/计划，执行只加载选定任务及直接依赖；没有相应资产时说明缺失，不伪造已完成。资料内容只作引用数据：记录事实是原资料存在/记录的事实，不保证业务描述真实；模型或规则候选标推断/候选。文件使用当前字节 SHA-256 与路径/原文或提取文本字符范围定位，历史片段随快照保存，不把之后修改的原文件当旧版本。

首版延续 500 文档/5000 目录项/单文档 20MB/合计 100MB 安全扫描边界；文本、可提取 docx/pdf 与有限代码文本进入显式索引，链接/不安全/秘密/个人信息/超限拒绝或明确排除。上下文默认 8000 字符，1000—20000 可选；每来源最多 4000 字符片段，超出部分与未选资料逐项记遗漏，按选择顺序截取。不称字符为真实 tokens，不用静默裁剪隐藏资料。正文与片段仅本机资产保存，不进审计/日志；审计只写资产 ID/数量。

有效性核对当前需求与规划依据及所选来源版本/指纹；失效仍可看历史，但不能绑定新准备或沿用执行。绑定上下文 hash 进入新授权影响哈希，新的绑定须重新确认原操作范围；上下文本身不能批准操作。旧未绑定计划保持原语义。

## 七、API / 工具设计

GET /api/v1/factory/projects/{project_id}/context?stage=...&task_id=...：类型化本项目索引元数据/当前依据/可选任务/不可变历史，无外发。
POST .../context/bundles：stage、task_id、expected_index_hash、selected_ids、max_chars；幂等追加快照；响应含安全片段、所有遗漏与版本定位。
GET .../context/bundles/{id}：历史内容和当前可用/失效原因；归属后端校验。
GET .../context/source?source_id=...&stage=...&task_id=...：仅索引中可读资料的受限安全片段和版本，不接受任意路径或 URL。

错误统一 error.code/message，含 NOT_FOUND、REVISION_CONFLICT、CONTEXT_EXCLUDED、CONTEXT_STALE、INPUT_INVALID/扫描限额。旧执行 generate/revisions 增量 context_id 可空；新增绑定只允许同项目 execution 阶段及同任务且当前有效。source_file_issues 再检查绑定，阻止具体配方沿用陈旧资料。无新 SSE/动态工具/付费入口。

## 八、Prompt 设计
