版本：V1.1；2026-10-09。依据主 PRD V1.1 FR24、阶段1技术适配声明、AGENTS、通用手册第二及第三部分。用户在 A19 本地提交 4a2a271 后授权继续。本文先于本切片代码形成。

## 一、目标与范围
交付确定性接续摘要、不可变摘要历史、脱敏接续包及项目审计视图和追加更正。摘要展示产品、有效需求引用、已完成范围、待验项、当前任务、有效授权、冲突与下一步。新摘要不执行任务，不继承聊天授权；旧摘要资料变化后明确需重新核对。审计更正仅修订说明，不改变需求、授权、执行或验收事实。保留全部既有记录。

## 二、技术适配与界面
沿用 FastAPI、SQLAlchemy/SQLite、Next.js/TypeScript；沿用现有本机访问保护和追加资产，不新增依赖、迁移、费用或外发。阶段2只加必要验收界面与需求页入口，正式前端仍为阶段3。不引入模型摘要或聊天导入：摘要由确定性后端从版本记录生成，资料不足明确待验，不按时间戳覆盖矛盾事实。

## 三、配置与模型
启动沿用根目录启动器，3000/8765。无新配置；无 Key，真实模型冒烟与 D2 样例评分仍待验。本切片实际模型费用及请求为零，不批准付费调用或外发。

## 四、数据与可信依据
RequirementRecord 追加 handoff_summary 和 audit_correction，schema_version=1。摘要保存源状态哈希、引用对象及版本、结构化投影视图、保存理由和操作者。源哈希覆盖项目业务表与安全文件清单，排除摘要本身及其审计，避免保存摘要令自身立即失效；审计更正不改业务事实。源的未检文件/排除资料明确提示，不能宣称全工程核验。冻结基线与较新草稿并列，规划及授权必须通过现有来源/文件有效性检查。完成范围仅来自仍有效的通过验收，不从计划确认、执行退出0或模型自报推断；真实效果待验仍展示。新身份恢复的历史只作来源，不作当前授权或通过证据。

新审计事件记录操作者、角色、对象、版本、时间与理由；旧事件缺失信息投影标记“未记录”，不回填或伪造旧事实。更正锁定原事件哈希与当前更正链哈希，保存说明/理由并保留原记录，跨项目、重复冲突或敏感内容拒绝。不会用更正提升业务权限或改变验收结论。

## 五、API 与错误
前缀 `/api/v1/factory/projects/{project_id}/handoff`：
- GET：当前实时摘要、源哈希、不可变历史及受限审计目录。
- POST `/summaries`：expected_state_hash、confirmed=true、reason；幂等保存，源变动409。
- GET `/summaries/{id}`：本项目历史摘要与 current 状态。
- GET `/summaries/{id}/download`：只含保存摘要、引用与安全说明的 JSON 接续包；不含聊天、原始文档、代码、密钥或审计原始 details。
- POST `/corrections`：event_id、expected_event_hash、expected_chain_hash、note、confirmed=true、reason；追加说明，链变化409。

所有输入/输出经 Pydantic 校验，错误为 error.code/message；继承本机鉴权、同项目归属和幂等锁。摘要导出只读取已保存资产，保存及更正遵循归档只读限制。敏感资料拒绝或明确排除；不存原资料到审计，输出不泄漏堆栈。短请求不使用 SSE。接续包最多1MiB，界面不能自动外发。

## 六、界面与验收步骤
