## 必须问（本轮三个）

### Q1 模型厂商与费用上限（已按推荐确认）
- 问题：有指定或禁用的模型厂商吗？一次任务和每个开发阶段最多花多少？这决定真实验证能否运行。
- 选项：按推荐 / 暂不付费，真实验证保留待验 / 自定义。例如“只用某厂商，每阶段最多 50 元”。
- 推荐：不限定厂商，由阶段 1 核实后推荐一家；每次任务最多 2 元、每开发阶段合计 100 元及 100 次请求，重试计入。
- 不选的后果：不能启用真实付费调用；无可靠报价的调用不得按零费用处理。这些金额是预算建议，不是价格承诺。

### Q2 资料与隐私边界（已按推荐确认）
- 问题：哪些项目资料可以发送给模型服务？这决定接入项目和 AI 执行的数据边界。
- 选项：按推荐 / 所有资料只能本地处理 / 自定义。例如“仅公开代码可以外发”。
- 推荐：首版仅外发经脱敏的非敏感资料，选择国内服务；密钥、密码、个人信息和企业机密不得外发；不得自动切换服务。
- 不选的后果：只做本地分析；具体提供方的数据地域、留存和调用方式需在阶段 1 验证，不能只凭品牌判断。

### Q3 数据留存（已按推荐确认）
- 问题：历史记录和运行日志需保留多久？这影响隐私与恢复。
- 选项：按推荐 / 全部保留，首版不自动清理 / 自定义。例如“日志保留 90 天”。
- 推荐：需求、决策、授权、验收和证据长期保存在本机；脱敏执行日志保留 30 天；原项目文件不自动删除；不建设自动外部备份。
- 不选的后果：不能确定自动清理规则，确认前不启用清理。原文将期限留给技术设计，此处为新增业务建议，需确认。

## 已发现的矛盾与依赖
- 工具包的 README 描述通用云上线、邀请码等路线，产品 PRD 明确首版本机交付。按产品 PRD 适配；不在首版额外引入云服务、企业认证或邀请码流程。
- FR01—FR24 范围较广，但不是要求一次做完。保留首版 P0 总范围，在阶段 1 提供子阶段和通过条件，逐段验证后推进。
- PRD 引用技术设计、流程、测试等配套文件。这些已在原“项目文档/产品工厂”目录找到；当前仅主 PRD 已复制。阶段 1 已按需读取设计、验收、实施与索引，不把配套文件默认为用户批准的技术方案。
- 模型厂商、价格、数据规则尚未核实，本阶段不作提供方推荐或真实调用。

## 已确认的交付顺序

用户于 2026-10-08 要求“先出文档，再开发，最后提交”。每个开发子阶段依次执行：

1. 先交当前阶段文档，写明范围、需求关联、输入与产物、异常、安全边界、验证计划和通过条件。
2. 满足阶段开工条件后实施代码，完成适用的自动测试、真实验证及人工验收。无真实 Key 的检查如实保留待验。
3. 更新项目状态、运行说明和证据包，再进行本地 Git 提交；不能用提交代替阶段验收。
