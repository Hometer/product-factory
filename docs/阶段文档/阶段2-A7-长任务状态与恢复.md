# 阶段 2 A7 技术开发文档｜长任务状态与恢复
> V1.1，2026-10-08，工程交付与待验。V1.0 在编码前形成；本版整理实现、验证和交接。依据主 PRD V1.1 FR11、第 10—11 节、AGENTS 与通用手册第二、三部分。文档 → 开发验证 → 证据/状态 → 最后本地提交，A1—A6 待验保留。

## 一、阶段目标
为已有三种受控命令配方增加持久步骤检查点、恢复核对历史、同一运行的安全接续；展示已发生步骤、待核对结果和恢复进度。刷新和重复恢复请求不产生新任务、不重复创建子进程。成功仅指本次配方产物规则满足，不代表阶段通过。
模型恢复页仅展示已有运行状态、外部尝试和保留预算，结果未知禁止自动重发。提供方查询/费用对账尚未接入，明确人工待核对，不提供随意改成功或释放预算按钮。A5 多文件补偿沿用原实现。
不新增配方、任意脚本、付费调用、外发、发布、FR12 通用暂停取消重试、完整自动开工或业务验收平台；工程交付不表示全部 FR11 适用能力与阶段验收通过。

## 二、技术适配摘要
延续 FastAPI/SQLite/Alembic、Next.js，无新增依赖或基础设施。原子保存检查点与运行状态，复用本机来源/令牌/幂等约束、项目所有权、A5 根目录锁及 A6 输入和授权核对。
界面是后端 MVP 的最小恢复验收入口，不提前铺开正式前端。检查点表增量迁移，旧记录不补写虚构检查点、不推断执行事实。

## 三、技术栈与模型
SQLAlchemy 事务、Pydantic 契约、受控 subprocess 和原轮询实现。恢复判断来自数据库启动意图、运行事实、文件痕迹与当前有效来源，不由模型判断。
无新增 Prompt、模型调用、外部数据发送、费用或云资源。阶段费用上限沿用原决策，不重置累计数。

## 四、环境与配置
工厂 3000/8765、静态端口 4200—4299；均只监听本机。环境确认仍 15 分钟有效，过期不能恢复旧批准。数据长期保存在忽略的 data/，原日志 30 天规则保留。
0007 只追加 command_checkpoints，不改写历史命令状态或业务结论；迁移前已用 SQLite backup 保存 data/a6-before-a7.sqlite3（0600）。新模块无秘密配置项；无 Key 时真实模型仍待验。

## 五、项目结构
追加 recovery.py、recovery_schemas.py、0007_recovery.py、test_recovery.py 和前端 recovery 页面；命令页增加入口，代理仅开放明确的恢复路径。
commands.py 在原运行事务中追加检查点，启动核对区分确定未执行与未知，未知保留项目占用；结果读取复用防链接、普通文件、大小、指纹与结构检查。main.py 增量安装恢复接口并报告 0007。

## 六、数据、资产与状态
CommandCheckpoint：id、project_id、run_id、created_at、受控 payload。只追加审批入队、启动意图、真实执行、结果落盘、重启核对、人工核对、确认恢复；旧检查点不覆盖。保存状态/步骤事实的 SHA-256、产物指纹/退出码和恢复依据，不保存文件正文、秘密或原始输出。
执行前先提交 launch_intent，再创建进程。本轮 queued 审批检查点存在、从未提交启动意图或执行/终结检查点、运行字段无启动/结果痕迹且私有运行目录不存在，才判确定未执行。遗留无检查点的 queued 保守为未知，目录或断链痕迹也阻止推断未执行。
重启时活动运行转 interrupted 并追加核对；确定未执行显示可审阅继续，已请求停止则禁止继续。starting/running/serving、不完整事实或旧运行无法核对时显示结果未知；不自动重发、不按历史 PID 杀进程，可能存活的未知运行继续阻止同项目命令与补丁。
终结结果保持；只读核对产物大小、指纹、结构及与保存的检查结果/输入事实/退出码一致性。成功还需退出码 0 和非空全部通过检查；冲突显示需排查，历史成功记录不被文字更改成新事实。存在 result.json 本身不能证明任务完成。
恢复只允许 interrupted → queued，沿用 run_id、asset_id、原批准与全部历史；重新检查来源、环境、原授权身份/撤销、目录/文件、配方版本、占用与端口。任一变化阻塞。启动时及实际创建进程前再次核对原授权身份；停止请求优先。失败/已停止/超时重跑归 FR12 或新批准，不走本轮恢复。
进度为本次批准配方步骤 0/1 或 1/1，不将执行计划其他步骤、产品完成率或阶段验收计为通过。

## 七、API / 工具设计
前缀 /api/v1/factory/projects/{id}/recovery。统一 error.code/message，错误不回显堆栈或秘密；POST 复用本机来源、令牌与幂等保护。GET 不改状态、不创建任务，采用提交后有限轮询，不用 SSE。
- GET：返回 Workspace，含命令 Task（Run、恢复结论、步骤进度、当前核对指纹、阻塞、检查点）和模型 Analysis（状态、尝试、保留/已记录费用、禁止本页调用）。每类最近 100 条、每运行最近 30 个检查点，返回总数并说明遗漏；旧历史仍保存。
- POST /runs/{run_id}/check：Review（confirmed=true、reason），返回 Task；幂等追加确定性核对，不将未知或保留预算改成成功/已结算。
- POST /runs/{run_id}/resume：Resume（confirmed=true、reason、checkpoint_id、expected_hash），返回同一 Task；绑定最新核对与当前事实，原子恢复同一运行。重复同一幂等键返回原任务；新键携旧事实冲突，不二次执行。
- 核对依据 4—500 字，拒绝秘密。主要错误为 NOT_FOUND、INPUT_INVALID、REVISION_CONFLICT、RECOVERY_BLOCKED、IDEMPOTENCY_CONFLICT；消息解释具体阻塞。结果未知无自动查询或盲目重试按钮。
模型摘要不包含候选正文、完整需求或秘密；未知预算沿用 A2 持久预留，不释放，不改变已记录费用。提供方查询和人工对账实际处理能力仍待后续适配。

## 八、Prompt 与权限
无新增 Prompt。模型不能判定已执行、批准恢复、解除占用、编辑预算或验收结论。恢复不扩大原配方/输入/授权，不能继承为任意脚本或外发授权。

## 九、验收界面
命令页点“任务恢复与核对 →”；进入恢复页仅读取。选择已有运行，看步骤、原任务/配方/授权、退出码、当前结论与检查点历史。填依据后“保存恢复核对（不执行）”；仅满足确定未执行及有效来源时，勾选确认并点“确认继续原任务”。
运行中有限轮询到结束；错误保留输入，重复请求复用幂等键，未保存依据离开提醒。未知无继续按钮，明确需独立工程/提供方核对；不能把未知改成成功、释放预算或解除未知占用。
启动：Finder 双击根目录启动产品工厂.command，看到“产品工厂已启动”后打开地址。出错提供页面错误码及运行 ID，不提供秘密。
