## 一、阶段目标

建立任务工程检查矩阵：测试、类型、Lint、构建、接口、恢复、界面七项默认待验，另列受控语法/格式检查。保存阶段/任务/需求基线/方案/计划、显式代码文件指纹和环境依据；追加结果记录执行情况、通过/总数、失败、警告、证据定位与责任人。自动来源与人工报告分开，首次失败和复测不可覆盖；相关代码、依据或检查标准变化后旧结果需复验。

本轮不实现 FR16 效果评分或 FR17 最终闸门/验收，也不扩大任意项目脚本运行权限。已有三种有限配方继续按原具体批准启动。本轮支持引用已完成 Python 语法/JSON 格式运行的可信产物作为补充检查，绝不把语法检查算单元测试、类型或构建通过。七项完整工程运行由执行者在现有授权流程执行后如实人工报告，平台标明报告性质，不能伪称亲自执行。

## 六、数据、资产与状态

复用追加型 RequirementRecord：verification_plan、verification_result，schema_version=1，无新迁移。计划保存任务、当前依据、显式文件（1—20 项）、七项检查要求、环境、修订、前版及改动理由。文件沿用 A10 安全索引与限制，不保存源码。标准/测试调整以新计划保存且必须写理由；所有原计划/结果保留。

人工报告保存检查种类、passed/failed/warning/pending/not_applicable、执行情况、报告方法/环境、责任人、确认、理由、计数、失败/警告与证据定位（仅文字，未由平台独立验证）；未执行只能 pending，N/A 必须解释。不提供平均分/自动验收结论。结果通过数量不能超过总数，测试通过需总数大于零且无失败；失败与警告不可被通过状态隐藏。

自动引用仅 Python 语法或 JSON 格式终态运行，限定同项目/同任务/同一执行准备、输入文件为本计划所选且指纹一致；从后端核对结果文件指纹、结构与原运行详情，状态和计数由代码计算，客户端不能填写通过。新引用采用 run_hash_version=2，仅摘要稳定的执行字段、输入与产物；日志到期清理不使有效回执失效。早期引用无该字段时沿用 v1，不补字段、不改历史正文或摘要，API 排除未设置字段。原运行未记录 Python 版本时明确标为未记录，不以当前工厂版本推断。与七项必需矩阵分开列补充检查。产物缺失、变动或不匹配显示证据异常。

GET 只读；保存使用幂等键、当前索引摘要、计划修订或计划摘要，冲突保留输入。旧计划不接受新结果，复测以当前计划追加。公开结果动态核对代码/需求/方案/计划/环境依据与最新计划；失效显示“需复验”，保留原结论；未选代码不在核对范围，明确提醒覆盖清单。正文不进审计，审计只记录 ID/类别。秘密/个人信息和当前配置 Key/令牌拒绝录入，历史遇到新配置秘密拒绝原文读取。跨项目归属由后端检查。

## 七、API / 工具设计

GET /api/v1/factory/projects/{id}/verification?task_id=T1：当前安全索引、任务、最新计划、当前矩阵、不可变历史与可引用运行摘要。
GET .../assets/{id}：本项目历史计划/结果、当时记录与当前有效性。
POST .../plans：task_id、expected_revision、expected_index_hash、files、criteria（七项完整）、reason；追加计划。
POST .../reports：plan_id、expected_hash、kind、status、executed、method、environment、responsible、reason、passed/total/failed、failures/warnings/evidence、confirmed=true；追加人工报告。
POST .../imports：plan_id、expected_hash、run_id；追加确定性补充结果，不启动任何配方。

统一 error.code/message；NOT_FOUND、REVISION_CONFLICT、VERIFICATION_STALE、INPUT_INVALID、CONTEXT_EXCLUDED、ARTIFACT_* 等；结构校验错误不回显内容。无新 SSE/长任务/工具或任意命令接口。
