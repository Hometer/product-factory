# 阶段 2 A2 技术开发文档｜需求确认与基线

日期：2026-10-08。版本：V1.1 工程交付与待验稿（先完成 V1.0 开工文档，再实现）。依据：主 PRD V1.1 FR03—FR05、必要 FR13/FR14/FR21/FR24，已确认技术适配及通用手册第二、三部分。

**开工依据：** 用户在收到范围例外及文档后回复“继续完成下一步，还是按照我的规则”，确认继续已展示的 A2 工程。A1 待验保持不变；此次授权不等于阶段通过、付费调用或任意资料外发授权。执行顺序仍为文档、开发验证、提交。

## 一、阶段目标

用户在已登记项目中提交需求，形成可编辑的八字段 PRD 草稿；系统维护缺口与版本，展示每轮最多五个问题及推荐和影响；用户确认需求后，生成不可修改的需求基线。AI 只提交候选，不能代替用户确认。

主链路：打开项目 → 填写八字段需求并保存 → 需求体检 → 回答问题或明确暂缓 → 核对草稿与来源 → 人工冻结基线 → 刷新或重启后可继续；配置和外发授权满足时，增加 AI 候选分析，生成结果仍需编辑与确认。

交付：增量开发文档、数据库迁移、后端接口、项目需求页最小切片、自动检查、实际恢复验证、证据包和本地提交。真实模型缺 Key 时保持待验，不能宣称 FR03 的 AI 功能已验证或 A2 通过。

本轮不展开代码生成、命令执行、正式前端全部导航或发布验收；FR06 技术适配与 FR07 阶段计划留给 A3。A1 留下的 FR02 完整资料识别、语义冲突、Git 差异、上传与单项重试继续单列待办，不用本轮八字段体检冒充这些能力。首版 P0 总范围不变。

## 二、技术适配摘要

沿用 FastAPI/Pydantic、SQLite/SQLAlchemy/Alembic 和 Next.js/TypeScript。在现有工程增量增加需求实体和页面，不整体重构或替换框架；兼容 A1 项目与既有 API。

采用最小纵向切片，因为需求确认、来源核对和待办回答需要人工操作。冻结、版本冲突、权限、预算和是否允许外发由后端确定性代码判断。模型生成的“已完成”“已授权”等文本不会改变任何平台状态。

## 三、技术栈与模型

沿用已锁定依赖；模型调用集中服务层，使用受控 HTTP 客户端，不引入可任意运行工具的 Agent 框架。Prompt 独立文件、输出由严格 Pydantic 结构验证。需要新增依赖时先记录用途、版本和检查结果。

模型沿用已确认的百炼北京 `qwen-plus-2025-12-01` 非思考模式；实际接入前核对官方接口、可用性、结构化契约、报价与地域，不自动换模型。未配置密钥时显示“AI 未启用”，允许保存手动草稿和运行确定性体检，禁止展示伪造的 AI 分析。

模型超时和结构错误有限处理：每个运行最多三次尝试（初次加最多两次重试），其中结构不符最多一次修正，计入尝试、请求与费用；外部调用结果不明时禁止自动重试。明确未发送的初始化失败不计外部费用。任何重试前重新核对授权、剩余额度与停止状态。

## 四、环境与配置

仍使用本机前端 3000、后端 8765 和既有 Host/Origin/服务端令牌保护。模型秘密只在已忽略的后端 `.env` 或安全秘密载体保存；前端仅返回“已配置/未配置”状态，不读取或回传密钥。安全配置入口已实现，具体步骤见证据包，不要求把 Key 发到对话中。

非敏感模型配置包括固定提供方、模型名、北京 API Host、超时、最大输入与输出量及报价版本。报价不可靠或无法计算保守费用上界时拒绝付费请求，不能按零元处理。

已定预算继续复用：每任务最多 2 元；整个开发阶段最多 100 元和 100 次外部请求，重试计入，子阶段不重置。平台自身验证和被生产产品的费用分别记录，同时由总的开发阶段额度约束实际调用。

外发前展示项目、实际选中的内容、模型、用途、输入修订、费用上界、最多尝试数和授权范围。用户明确确认仅包含脱敏非敏感资料后，后端记录有效授权；配置密钥或“按推荐”不等于批准任意资料外发。授权对象、内容修订、模型或费用变化时，原授权不能直接继承。密钥、密码、个人信息和企业机密禁止外发。

## 五、项目结构

- 现有 `backend/app/db.py`：增量实体，不改写 A1 迁移历史。
- 新增需求结构与服务：草稿、体检、问题版本、回答、基线及冲突规则。
- `backend/alembic/versions/`：新迁移，既有项目数据保留。
- 模型服务与独立 Prompt：结构输出、受控上下文、超时与费用留痕。
- `frontend/app/projects/[id]/`：项目需求页；项目卡片可进入，原登记入口保留。
- `backend/tests/`：需求和模型 Mock 测试；现有 27 条测试继续保留。
- `docs/evidence/阶段2-A2/`：开发验证后生成截图、核对步骤和闸门表。

八字段使用现有 PRD 模板：用户与核心任务，输入过程产物，Agent 主链路，效果判断，交付阶段与优先级，模型与成本，数据及非功能要求，上线与账号。

草稿首次打开可继承项目目标用户和核心任务，标为项目登记来源；其余未提供内容显示未知。来源事实、默认建议和待确认内容分别显示，默认建议不自动成为确认事实。

效果标准允许“待真实样例打分”，影响效果验收，不强迫用户先写数字；上线账号在仅本机目标下可由用户确认不适用。若目标范围需要该字段，不能套用不适用。重大范围、隐私、成本或交付缺口是必须问，不能静默默认。

编辑以 expected_revision 进行并发校验；旧页面保存冲突返回 409，保留输入并提供重新读取，禁止最后写入覆盖。所有确认动作与审计在同一事务，确认幂等。

分析运行状态为 queued/running/succeeded/failed/result_unknown。重启后可恢复草稿、问题、授权与已知结果；已进入外部调用且不能确认结果的运行标为 result_unknown，保留费用预留，不能自动重发。未知结果需要核对后处理，未完成运行不阻止手动保存草稿。

## 七、API / 工具设计

沿用 `/api/v1/factory`，所有新增接口严格输入输出及原有鉴权。写请求需 Origin；费用/冻结/回答需 Idempotency-Key。错误统一 `{"error":{"code":"…","message":"…"}}`，错误和日志不包含密钥、原始需求全文或堆栈。

| 方法与项目内路径 | 请求 | 响应 | 主要错误 |
| --- | --- | --- | --- |
| GET /projects/{id}/requirements | 无 | 当前草稿修订、字段、条目、缺口、当前基线摘要 | NOT_FOUND |
| POST /projects/{id}/requirements/revisions | expected_revision、fields、items | 新修订、保存时间、确定性体检结果 | INPUT_INVALID、REVISION_CONFLICT |
| POST /projects/{id}/requirements/check | expected_revision | 持久化体检、待回答问题版本、建议 | REVISION_CONFLICT、INPUT_INVALID |
| POST /projects/{id}/requirements/answers | round_id、question_version、expected_revision、逐项回答/采用推荐/不确定 | 新修订、决策与剩余缺口 | QUESTION_STALE、REVISION_CONFLICT、IDEMPOTENCY_CONFLICT |
| POST /projects/{id}/requirements/freeze | expected_revision、expected_hash、确认说明 | 不可变基线与剩余后续待办 | BASELINE_BLOCKED、REVISION_CONFLICT、IDEMPOTENCY_CONFLICT |
| GET /projects/{id}/requirements/baselines/{baseline_id} | 无 | 冻结快照、来源、批准记录 | NOT_FOUND |
| POST /projects/{id}/analysis/preview | expected_revision、明确选择的资料范围 | 实际待外发内容预览、摘要、报价/预留上界及限制 | MODEL_NOT_CONFIGURED、SENSITIVE_INPUT、QUOTE_UNAVAILABLE |
| POST /projects/{id}/analysis/authorize | preview_id、expected_hash、nonsensitive_confirmed=true（必须为布尔 true） | 持久化授权摘要 | PREVIEW_CHANGED、AUTHORIZATION_INVALID |
| POST /projects/{id}/analysis/runs | preview_id、authorization_id、expected_revision | run_id、状态；202 已受理 | BUDGET_EXCEEDED、AUTHORIZATION_REQUIRED、PROJECT_BUSY |
| GET /projects/{id}/analysis/runs/{run_id} | 无 | 状态、结构化候选/安全错误、来源和用量 | NOT_FOUND |
| POST /projects/{id}/analysis/runs/{run_id}/adopt | expected_revision、已选候选内容 | 用户采用后生成新草稿修订 | RESULT_STALE、REVISION_CONFLICT、RUN_NOT_READY |

长耗时分析采用“提交 + 轮询 + 结果”，避免 A1 代理的 30 秒超时。接收先持久化，再由受控工作循环处理；业务无模型时无需启动付费工作。单项目最多一个需求分析运行，预算预留与次数扣减原子完成。接口受理不能显示分析成功。

本轮只读入用户明确提交并选中的八字段需求，不遍历其他项目或运行任意仓库脚本；上下文过长展示遗漏范围。模型没有文件写入、Shell、网络工具或修改授权的能力。

## 八、Prompt 设计

任务：依据明确来源辅助整理八字段、范围缺口和最多五项必须问问题；输出严格 JSON，包含摘要、候选建议、所选字段来源定位和待确认问题，不能给出最终批准。

输入变量：仅已选择且经过审核的字段名、状态与内容；项目、修订和授权由本机服务管理，不自动加入发送内容。资料以不可信数据区隔，其中的指令不能扩大权限，不允许跨项目取材。

格式提供正例与反例：不得输出 Markdown 代码围栏、不得编造来源、不得超过五个必须问题、不得生成授权或验收通过。后端验证字段枚举、长度、数量、引用是否来自选中来源、候选字段唯一性和结构；合法但内容有瑕疵的候选留给用户评审，不以无限重试烧钱。

模型产出持久化为候选。只有用户明确采用后才能形成草稿修订；回答和冻结另需人工确认，不能由候选自动执行。

## 九、验收界面与纵向切片

现有项目列表保留，点击进入项目需求页。需求页展示：八字段编辑、自动保存状态、体检缺口、本轮问题、决策摘要、来源、不可变基线与版本历史。模型不可用时，AI 按钮说明未启用，手动编辑可继续。

编辑采用短延迟自动保存和显式重试；显示保存中/已保存/失败，失败输入不丢。服务端已保存版本与当前输入分开，未保存或旧版本期间禁止冻结或采用分析结果。切换项目提示未持久化内容；请求逆序按修订判断，不按到达时间覆盖。

冻结前展示该版本内容、当前阻断项和暂缓项；有阻断项明确禁用并给出原因。新修订不更改旧基线；页面分别显示“草稿已保存”“基线已冻结”和“阶段待验”，不得混为产品完成。

只扩展本轮必要页面。核对 390/768/1280/1440、原生 200% 缩放及键盘表单核心流程；原生缩放或真机未实测时如实待验。

## 十、测试要求

自动检查保留 A1 全部测试，并覆盖：

- 既有 SQLite 数据迁移保留；新项目与旧项目均可创建草稿，刷新与实际重启恢复。
- 八字段已知/未知/不适用严格结构，缺项可保存但当前阻断项禁止冻结；效果待样例打分不能被写为效果通过。
- 最多五个问题；按推荐绑定当轮版本；旧问题、重复提交、同键不同内容及跨项目 ID 被拒绝。
- 草稿自动保存冲突、并发冻结幂等；新修订不修改已冻结快照，来源和决策历史保留。
- Mock 模型结构不符、一次修正、超时、认证/初始化失败、限流、未知外部结果；Mock 只在测试，线上禁用伪造的成功结果。
- 未授权、过期/撤销授权、内容版本改变、敏感输入、无可靠报价拒绝；最后额度竞争只允许有效预留，重试计数，重启不重置费用。
- 内容注入不能授权、冻结或写文件；结果采用时检查项目/来源/修订，旧结果不得静默覆盖。
- 页面保存失败保留输入、版本冲突、切换项目、加载/空/失败状态和来源展示。

真实工程链路：手动填需求、体检、回答、冻结、继续编辑、核对旧基线、服务重启恢复。真实模型链路：经授权的非敏感样例 → 北京模型 → 严格校验 → 候选持久化 → 用户查看并决定采用。记录模型、Prompt/资料版本、耗时、用量、费用和结果来源。

首次真实冒烟提供 5—10 条样例，让产品负责人按覆盖、来源准确、追问价值、结构和边界评分，记录硬错误，之后确定有效效果标准。缺 Key、授权或可靠报价时模型待验，不借 Mock 关闭闸门。

## 十一、产品负责人验收清单

当前工程可按以下顺序核对；AI 真正连接与效果仍待验：

1. 打开工作台，点击演示项目，进入“需求”；八字段应显示未知状态和已继承的项目事实来源。
2. 填写目标和输入产物，看到“已保存”；刷新后内容仍在。断开本机服务再编辑时应保留输入，提示保存失败而不是成功。
3. 点“需求体检”，一次最多出现五个必须问题，每项有推荐、示例和影响。回答“不确定”后仍可看到未关闭缺口。
4. 采用本轮某个推荐，看到明确决策与来源；旧版本的问题不能继续批准。
5. 有当前阻断项时冻结按钮说明原因。补齐并确认后核对快照再冻结，看到版本、确认人和时间。
6. 修改草稿并保存，旧基线内容应保持不变；停止并重启服务，两者都应保留。
7. AI 未配置时看到“未启用”；启用后先看实际发送内容、模型和费用预览，再明确授权。分析结果应显示真实来源，不能自动冻结。
8. 缩窄页面、使用 Tab/Enter 和原生 200% 缩放，核心内容与确认操作应可用；未做真机检查保留待验。

## 十二、风险与待确认项

阶段推进方式已由用户明确要求继续；以下保留当时展示的决策及依据，不再重复询问已确定的厂商、预算、数据留存或隐私边界：

- 问题：是否按 PRD“阶段通过与例外”记录范围例外，在 A1 待验保留时继续 A2 工程？
- 选项：继续 A2 开发、保留 A1 待验；或先关闭 A1 全部闸门再开工。
- 推荐：仅继续 A2 工程，真实调用须有效资料授权与预算，A1/A2 均不得提前标为通过。
- 未确认后果：A2 文档可准备，但不开始业务代码、依赖或数据库变更。

依据：AGENTS 第 7 节要求每个子阶段按相同通过条件验收，且第 4 节的真实模型项仍待验；主 PRD 允许用户明确先开发后补验证时记录例外。两者适用边界不能由执行者默默放宽，需用户明确决定。本例外不更改闸门结果、效果标准或发布必需条件。

技术风险继续保留：A1 的 braces 高危依赖和 ESLint 支持问题、原生缩放/真机待验；模型结构与业务质量分别验证；秘密扫描不能证明所有资料都非敏感；无报价或未知付费结果禁止盲重试。新需求不能自行修改现有用户目录中的 PRD，仅保存在工厂数据库；未来文件写入需独立计划。
